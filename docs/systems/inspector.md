# The editor (roadmap 0.6)

Per [ADR 0009](../adr/0009-code-organisation.md), the Inspector is the one tool app. Per [ADR 0010](../adr/0010-editor-reads-plugins.md), it's the editor, which reads only the imported plugins and draws them with the runtime's code. New research into formats uses the CLI's dumps and exports.

`src/Aidyn.Inspector` is a Godot app. Run it with `tools/godot.ps1 --path src/Aidyn.Inspector` (build it first with `dotnet build`, or open it in the editor). It links the runtime's files in its `.csproj` (`ActorAnimator`, `ChunkScenery`, `N64Material`, `ParticlesView`, `PartyTabView`, `UiScreen`, `UiPainter` and the rest, under `Shared/`), and the runtime uses nothing of the editor's: code flows from the core to the runtime to the editor.

## The editor's game

The editor holds one game, the core's `GameState` ([saves](saves.md)), which flag pages show and set, scripts play against and change, and the party's pages show or try things on. A flag page's buttons change it:

- **Load checkpoint…** reads an ares state (see the [reference rig](../reference-rig.md)) as a save made from it loads (`CheckpointSave`), and says whether the core's network reproduces the console's derived flags, marking any the console has otherwise (such as the new journal entry flag, which loading clears). A state without a party gives a new game's party with the checkpoint's flags.
- **Load save…** loads a save from the data folder's `saves` and lists anything it couldn't use.
- **Save game…** saves the game as the editor has it, where the save or checkpoint it came from stood, so the runtime can start from it (`--save`).
- **New game** goes back to a new game's.

## Plugins

It loads the plugins folder as the runtime does (`PluginSet.LoadInstalled`: `aidyn.base`, then the rest ordered by their dependencies and load-after hints, by ID where those leave it open), and shows `BasePlugin.Diagnose`'s words instead of loading when the import is missing or by another importer, from the data folder (`AIDYN_DATA`, else `%LOCALAPPDATA%\Aidyn`) or wherever **Plugins folder…** points. **Import ROM…** runs the importer into that folder's `aidyn.base`, as the game's first-run screen will, and reloads.

- **The list** is every record and every asset, by type: `PluginCatalog` in `Aidyn.Plugins`, which the tests check against a fresh import. Scenes, textures and UI images are assets with no record, so they're listed by their asset's ID. The Borg column is the archive index a base-game ID's hex key stands for. The search filters by ID, Borg index or summary (`I08` finds the chunk's map).
- **Links.** Any field whose value parses as a record ID is a link, so new record types need no editor code. A link to a record no plugin has yet, such as a flag, opens a page showing what names it.
- **Preview** (`RecordBrowser` picks the panel). Each kind of record previews with the runtime's or the core's own code, against the editor's game where rules come in:
  - **A scene** in the model view (`ModelView`) with the N64 material: its animations, looped and scrubbed by the tick, **Wireframe**, **Scene camera** (the scene's own camera at 4:3, with a cinematic shot's near and far planes while its animation plays, which the cinematic table sets in place of the Borg3's) and **Emitters**, which marks each particle emitter on the scene's locators. A clip's length is one loop, as the runtime counts it.
  - **An actor** (`ActorPanel`): its scene in its initial state, without Alaron's head, and its states and branches. **Root in place** zeroes the root's position as the game draws it, and **Drive** runs the state machine for a request with the runtime's `ActorAnimator` and the core's `ActorMotion`, moving it by its root motion and starting its emitters as it enters states, drawn by the runtime's `ParticlesView` ([particles](../formats/particles.md)): `--record aidyn:actor/0x2BD7 --drive 5` shows Oriana's orb.
  - **A flag** or **journal entry** (`FlagPanel`): its value in the editor's game, its label, a derived flag's formula with each input's value (the first input is the lowest bit), and a check box to set a plain flag.
  - **A script** (`ScriptPanel`): its nodes as a graph of cards, a card being a run of lines that each lead only to the next. **Play** runs it with the core's `ScriptRunner` against the editor's game (`GameState.RunScript`, so it draws from the game's random streams as the runtime's do), drawing the conversation box as the game does ([ui](ui.md)). What the script asks about (members, items, gold, any skill check fixed at a step) can be changed in place; what it does changes the editor's game, and its cues are logged.
  - **An entity** (`CharacterPanel`): its character sheet from the core's `Character`, with training quoted by the core's `Training`, experience to award, and equipment taken off or put on by the core's rules. A member of a loaded game's party can show that game's sheet.
  - **A trainer's character page** ends with the training window on the editor's game ([ui](ui.md#training)), as a script's Train opens it.
  - **A weapon, armor or item, a shop, a loot table or a recipe** (`ItemPanels`): tried on a copy of the editor's party (`GameState.CopyParty`), so trying things leaves the game alone. A shop opens its window on the editor's game ([ui](ui.md#the-shop)), as a script does, so the barterer pays its Stamina; a loot table rolls once, opening the loot window on the editor's game ([ui](ui.md#the-loot-window)), or 10,000 times for its averages.
  - **The inventory record** (`aidyn:inventory/0`, `PartyTabPanel`): the editor's game's party in the pause menu's Party tab, drawn by the runtime's `PartyTabView` ([ui](ui.md#the-pause-menu)), with buttons for the controller's, acting on the editor's game. It, `BarterWindowPanel` and `TrainingWindowPanel` are `MenuWindowPanel`s, which hold the UI screen and its options, the button bar, the Details checkbox and `--press`'s names for the window (an `IPartyWindow`) they preview.
  - **A map set or a map** (`MapSetView`): drawn whole with the runtime's `ChunkScenery` (ADR 0010), each object at its nearest level of detail; a map is its 3×3 framed on its own, and **Whole map set** loads the rest. Switches for terrain, scenery, collision coloured by surface or role (`CollisionLayer`), the chunk grid, the map objects by type (`MapObjects` holds their colours; their names and the chunks that place a map are Plugins' `MapObjectKinds`, `MapPlacements` and `PluginCatalog.Describe`, which the `flag` command uses too), the Expansion Pak, and **Flags**, which leaves out what isn't there by the editor's game's flags (the core's `MapObjectPresence`). The camera is `Orbit`.
  - **A map object** (`aidyn:voxel/<map>/<index>`): its map's chunks with it picked, its radius and a line to each object it names. A container can be opened in the loot window, rolling what it holds without setting its flags, and a camera object looked through, from where the player triggers it.
  - **Textures, UI images** and the images other records name (`ImageGallery`), blown up; click one to open it.
- **Fields:** the merged record as its JSON, with the plugins that set each top-level field, in load order (`PluginSet.Setters`). Lists come in pages of 256. The header says which plugin defines the record, which patch it, and which plugin each asset file comes from.
- **Used by:** every record that names this one, with the fields that do. Terrains show nothing here, since chunks name them by number rather than record ID; a record ID there would fix that at the next importer change.
- **Atlas** (`AtlasView`, over `QuestIndex` in `Aidyn.Plugins`): for a flag, what sets, clears and reads it, from scripts, derived flags, journal entries, the engine and map objects; for a script, what it reads and sets and what starts it. Below, the graph around it, upstream, downstream or both, up to 160 records (`AtlasView.NodeLimit`), hiding the flags the engine writes its state into unless asked. Key items and members count as their flags: giving a key item sets its held and region flags, and AddMember sets a member's joined flag. The CLI's `aidyn flag` reads the same index over the installed plugins. Boss flags, which winning a battle sets (`EngineFlags.BossFlags`, which only labels them so far), aren't in the index yet; they come with combat (2.5).
- **Searching script text:** the list's search also finds scripts by what they say, from three letters, and shows the first line that matches in place of the summary.
- **Many objects at once.** Every mesh the N64 material draws has instance uniforms, so the project raises Godot's global shader variable buffer (`rendering/limits/global_shader_variables/buffer_size`) for a whole map set's worth.
- **Freeing what's out of the tree.** Godot frees only what's in the tree when it quits, and reports everything else leaked, one by one, slow enough after a map set to look like a hang. The browser swaps the model view and the map view in and out of the preview rather than rebuilding them, and `Models` keeps each scene's parsed template out of the tree, so `RecordBrowser` frees the view not showing and disposes the models when it's deleted, as `Game` disposes its models. Anything else kept out of the tree needs the same.
- **Command-line flags,** for scripts and screenshots: `tools/godot.ps1 --path src/Aidyn.Inspector -- --record aidyn:mapset/0 --tab preview --screenshot out/shot.png` opens a record, saves the window and quits. `--tab` takes `preview`, `fields` or `used-by`, and `--data` a plugins folder. `--checkpoint <state>` and `--save <save>` load a checkpoint's or a save's game, `--play <moves>` plays a script that many moves (taking first choices), with its conversation box, or the Party tab, at `--zoom <1-3>`, `--ui-filter pixels|videoout|smooth`, `--aspect 4:3|16:9` and `--ui-lines <n>`, `--drive <request>` drives an actor, `--wireframe 1` and `--scene-camera 1` set those switches, `--collision surface|role` colours a map's collision, `--member <slot>`, `--list inventory|spells|skills|stats`, `--row <n>` and `--details 1` set the Party tab, `--press a,b,up,down` presses its buttons in turn, `--roll 1` rolls a loot table's page or opens a container's in the loot window, whose buttons `--press` also takes with `left` and `right`, as it does a shop's window's with `cup` and a trainer's training window's with `cleft` and `cright`, `--look 1` looks through a camera object's camera after the wait, and `--wait <seconds>` waits before the screenshot. `--ui-screenshot <png>` saves the UI screen too, in its own pixels. It gives up after a minute, so a hang can't block a script. `Editor` parses them and takes the screenshot with the runtime's `CommandLine`, which it links.
