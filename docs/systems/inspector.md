# The editor (roadmap 0.6)

Per [ADR 0009](../adr/0009-code-organisation.md), the Inspector is the one tool app. Per [ADR 0010](../adr/0010-editor-reads-plugins.md), it's the editor, which reads only the imported plugins and draws them with the runtime's code. On Sep 30, 2026 it reached parity with the three.js scene viewer, map viewer and quest atlas, and they were deleted along with the raw Borg browser, its first feature. New research into formats uses the CLI's dumps and exports.

`src/Aidyn.Inspector` is a Godot app. Run it with `tools/godot.ps1 --path src/Aidyn.Inspector` (build it first with `dotnet build`, or open it in the editor).

## The editor's game

The editor holds one game, the core's `GameState` ([saves](saves.md)), which flag pages show and set, scripts play against and change, and the party's pages show or try things on. A flag page's buttons change it:

- **Load checkpoint…** reads an ares state (see the [reference rig](../reference-rig.md)) as a save made from it loads (`CheckpointSave`), and says whether the core's network reproduces the console's derived flags. Any flag the console has otherwise is marked, such as the new journal entry flag, which loading clears. A state without a party gives a new game's party with the checkpoint's flags.
- **Load save…** loads a save in the port's format, from the data folder's `saves`, and lists anything it couldn't use.
- **Save game…** saves the game as the editor has it, flags, party and all, where the save or checkpoint it came from stood, so the runtime can start from it (`--save`). So a checkpoint can be loaded, changed by setting flags or playing scripts, and saved for the runtime.
- **New game** goes back to a new game's.

## Plugins

It loads the plugins folder as the runtime does (`PluginSet.LoadInstalled`: `aidyn.base`, then the rest by ID), from the data folder (`AIDYN_DATA`, else `%LOCALAPPDATA%\Aidyn`) or wherever **Plugins folder…** points. **Import ROM…** runs the importer into that folder's `aidyn.base`, as the game's first-run screen will, and reloads.

- **The list** is every record and every asset, by type: `PluginCatalog` in `Aidyn.Plugins`, which the tests check against a fresh import. Scenes, textures and UI images are assets with no record, so they're listed by their asset's ID. The Borg column is the archive index a base-game ID's hex key stands for. The summary names what the ID alone doesn't: where a map set places a map (`Overworld I08`) and what objects it holds, an actor's states and scene, a terrain's sky gradient, an image's size, and for a bare asset how many records use it. The search filters by ID, Borg index or summary, so `I08` finds the chunk's map. Enter opens a record ID typed in full, or the only match.
- **Links.** Any field whose value parses as a record ID is a link, so new record types need no editor code. Double-click one in the fields or in Used by to open it on its preview; picking from the list keeps the tab you're on. Back and forward are the ◀ ▶ buttons, Alt+Left and Alt+Right, or the mouse's side buttons. A link to a record no plugin has yet, such as a flag, is dimmer, and opening it shows what names it.
- **Preview.** A scene in the model view, with the N64 material. Drag to turn, right-drag to pan, scroll to zoom.
  - **Animations** play looped, one at a time. The slider scrubs by the tick; with the view focused, space plays and pauses, and comma and full stop step a tick. A clip's length is one loop, as the runtime counts it.
  - **Wireframe**, and **Scene camera**, which looks through the scene's own camera at 4:3, as the scene viewer's did.
  - **Emitters** marks each particle emitter on the scene's own locators (the importer's `emitter i` nodes), drawn through the model in its particles' brightest colour, and counts the scene's emitters and how many sit on its locators.
  - **An actor** is its scene in its initial state, without Alaron's head for now, with its states below: each state's animation, length and branches, with the interrupting ones in orange. Clicking a state plays its animation. **Root in place** zeroes the root transform's position as the game draws it. **Drive** runs the state machine for a request with the runtime's own `ActorAnimator` and the core's `ActorStateMachine`, so the actor branches, rolls and moves by its root motion as it does in the game, and the camera follows it over a grid a scene unit square. Clicking a state enters it, and ⟲ puts the actor back.
  - **A flag** shows whether it's set, its label, a derived flag's formula with each input's value (the first input is the lowest bit), and the journal entry it adds. A plain flag has a check box to set or clear it and see what follows. A journal entry shows its text, the flag the journal lists it by, and the flag that adds it. The values are the editor's game's (below).
  - **A script** is its nodes as a graph of cards. A run of lines, each the only way into the next, is one card, read down; a card ends where the script branches, and a new one starts where branches join. Cards read across: a card's first link goes to its right, level with where it leaves, and each other branch goes below it, as high as it fits without meeting the cards above. Double-clicking a link scrolls to the card at its far end. Ifs are gold, cases orange and menus blue. Each node shows its text, its ops with the records they name as links (speakers, flags, items, the script a random line comes from), and, at the end of its card, where it goes. The graph opens centred on the first node, with the zoom controls at the bottom right beside the minimap, as in the Atlas. **Play** runs it with the core's `ScriptRunner` against the editor's game, so load a checkpoint or a save on a flag page first to play a scene as it stands there. The page shows the line and its speaker, and the choices, and above them the conversation's box as the game draws it (see [ui](ui.md)); the graph centres on the node on screen and lights it up in its card. It plays against the game's party (`Party`, see [characters](characters.md)): the loaded checkpoint's or save's members and gold, or a new game's Alaron alone. The script's checks of members, stats and the party's size read it, and what the script does changes it: members join as their records start them and leave, experience is awarded and levels reached, camping heals. Skill checks roll as the original's do, from the party's skills and stats, and each one is logged with its result; any of them can be fixed at a step from 0 to 21 instead, to explore a branch. Check boxes put the members the script asks about in the party or take them out, and **Reset party** goes back to the party the game was loaded with. The party lasts across plays, as the flags do, and other pages see what the script did to it. Its items are its own (`Party.HasItem`, `TakeItem` and the inventory): the loaded inventory and what its members wear, or a new game's, and a check box for each item the script asks about gives the party one or takes every one. Key items set and clear their flags in the editor's flags as they come and go. Gold is the party's, with a box to change it where the script checks or takes it. A script that ends in a shop links the speaker's shop. Below, it logs the cameras, actors and sounds it cues, what it gives and takes, and each flag it sets or clears. Playing changes the editor's game, as a flag's check box does; the game is the script world (`IScriptWorld`), and the editor only logs what goes through it.
  - **An entity** is its character sheet, from the core's `Character` as its record starts it: portrait, level, hit points, experience and the next level's, aspect, school and True Name, then its attributes, skills and spells with their modified values and what raising each costs (the core's `Training`). Its True Name follows the editor's flags. **Award experience** adds experience as a script or battle does, and says what level it reaches. The trainer picker quotes training after a battle (experience only, no new skills) or at any plain NPC, recruit or free trainer, with gold from **Party gold**; a trainer offers what it knows, up to its own level. **+** buys a point, and **Reset** goes back. A member of a loaded game's party can show a copy of that game's sheet and gold instead. Below, its **equipment**, as the record starts it (`Character.Create` with the items: its armor, its shield if it has the skill, and the first weapon it can wield) or as the checkpoint has it: each piece with its icon and what it does, which applies to the sheet above, and a button to take it off by the core's rules. **Put on** tries any weapon, armor, shield or gear, giving the character one first if needed, and says why the core refuses it. Then its protection (armor's and the shield's counted in), damage, morale, the experience it's worth and its resistances.
  - **A weapon, armor or item** is its icon, what it is (a weapon's skill, damage, hit, range and element; a shield's defense; what wearing it needs), what wearing it does (`GearBonuses`, with its spells as links), a key item's flags, and **Equipping it**, tried on the editor's party: for each member ("New game Alaron" without a loaded game), what putting it on would change on their sheet, what it replaces, or why they can't, with the number they fall short of, from `Party.Equip` on a fresh copy of the party. A scroll is read instead, as in trek (`Party.ReadScroll`), under **Reading it**.
  - **A shop** is its shopkeeper and stock at the editor's party's prices (`Shop.Open`): who barters and the barter factor, each item's base, shop and buying price, what the shop would pay for one, and the line appraisal shows. **Buy** and **Sell one** trade with the core's rules against a copy of the party, its gold and inventory; **Reset** opens the shop again.
  - **A loot table** is its gold, reagent and drops with their chances, and what beaten enemies drop. **Roll** rolls it as a container opens (`Containers.Roll`) and opens the loot window on it against the editor's game, drawn by the runtime's `PartyTabView` ([ui](ui.md#the-loot-window)): its gold goes to the game's party, and what's taken or dropped stays in the game, to save for the runtime. The buttons are the stick's four ways, A and B, with C-down's details and the UI screen's options. **Roll 10,000 times** gives the average gold and how often each item comes.
  - **A recipe** is its ingredients and product as links, the level and step it needs, and, under **Making it**, for each of the editor's party whether they're offered it and how often they'd make it: `Crafting.Make` on a fresh copy of the party, once for each roll of the d100.
  - The party on these pages is a copy of the editor's game's (`GameState.CopyParty`), with its inventory, so trying things on leaves the game alone: a loaded checkpoint's or save's, or a new game's Alaron, with the weapons he doesn't wield.
  - **The inventory record** (`aidyn:inventory/0`) is the editor's game's party in the pause menu's Party tab, drawn by the runtime's `PartyTabView` (see [ui](ui.md#the-pause-menu)): the buttons change the member and the list, as C-left, C-right and the stick do, **A** and **B** use the cursor's row and close popups, acting on the editor's game so it can be saved for the runtime, **Details** shows what C-down shows for the cursor's row, and hovering a row or scrolling moves the cursor. Its screen has the conversation box's options, so the classic layout shows at 240 lines and the wide one at 16:9 and 360 lines or at 480.
  - **A map set** is drawn whole with the runtime's code (ADR 0010): each chunk's scenes and scene objects as `ChunkScenery` builds them for the runtime's chunk streamer, each object at its nearest level of detail, with billboards turned to the camera and textures scrolling. A **map** is the 3×3 chunks around it, as the game loads them, framed on its own; **Whole map set** loads the rest. Chunks load nearest first, a few a frame; the overworld takes about 9 seconds and draws at about 30 fps whole. Drag to turn and right-drag to pan. Scrolling moves the camera toward whatever collision is under the cursor, a fifth of the way a notch, and makes that the point it turns about, so it can close in on the ground from any height; over nothing, it flies along the cursor's line. W, A, S and D fly forward, left, back and right, E and Q up and down, Shift faster, at a pace that suits how far away what's in view is. Double-click the ground to turn about that point. The clip planes are fixed, so nothing near the camera is cut away however far out it started.
    - **Terrain** and **Scenery** switch the chunks' scenes and the scene objects' models. **Collision** colours each triangle by surface or by role, see-through over the scenery. **Chunk grid** outlines and names each chunk.
    - **Objects** puts a dot on every map object, coloured by type as the map viewer did; the legend below counts each type and switches it, with scenes and reference points off to start with. Hovering names the object under the cursor, or else the chunk, surface, role and whether the triangle is passable or see-through, with its position in the map set and in the chunk. Clicking a dot opens the object.
    - **Expansion Pak** shows the objects and scenery for playing with it, as the runtime does, or without, and dims the triangles that are passable without it. **Flags** leaves out what isn't there with the editor's game's flags as a chunk loads (the core's `MapObjectPresence`): a new game's, or a checkpoint's or save's loaded on a flag page.
  - **A map object** (`aidyn:voxel/<map>/<index>`) has a page of its own: its map's chunks with it picked, its radius drawn and a line to each object it names, and its fields beside them, from its map record. A container has **Open it in the loot window**, which rolls what it holds as opening it does (a source's reagent at the party's harvest share) and opens the loot window in a window of its own, as the loot table's Roll does, without setting its flags; with no items it gives the gold alone. A camera object that moves the camera has **Look through it**, which puts the view at its reference point, aimed at where the player triggers it: the middle of its reach, or of the trigger triangles that name it, 1.55 above the floor. Its header says what it is and where, Used by lists what names it (a teleporter arriving at a reference point, a party's home node), and the Atlas its flags. Links between objects open the other object, in another map set if need be.
  - **Other kinds.** A texture or UI image at its size, blown up. Other records show the images they name, such as a terrain's sky gradient or the sky's sun, moon, stars, clouds and flare; click one to open it.
- **Fields:** the merged record as its JSON, with the plugins that set each top-level field, in load order (`PluginSet.Setters`). Lists come in pages of 256. The header says which plugin defines the record, which patch it, and which plugin each asset file comes from.
- **Used by:** every record that names this one, with the fields that do, which is Bethesda's "use info". It's how to find what places a scene, or which maps' objects a flag gates. Terrains show nothing here, since chunks name them by number rather than record ID; a record ID there would fix that at the next importer change.
- **Atlas:** the quest atlas, over the plugins' records (`QuestIndex` in `Aidyn.Plugins`). For a flag, what sets, clears and reads it: script ops by node, scripts' done and battle flags, derived flags' formulas, journal entries, the engine, and map objects: their gates, what using them writes (containers opened or destroyed, parties talked to or beaten, locks picked, traps disarmed, secret doors found, triggers). For a script, journal entry or derived flag, the flags it reads and sets, and for a map, its objects'. A script also lists what starts it: the dialogue objects and monster parties that start it, and the scripts whose RandomLine ops take lines from it. A map object is named by what it is and the chunk it's in, such as "Monster party: Male Commoner, in Overworld E15". Below, the graph around it, with edges the way things happen: from what sets a flag, to the flag, to what reads it, and from what starts a script to the script. It follows upstream (what leads to it), downstream (what it leads to) or both, for a number of steps, up to 160 records, and hides the flags the engine writes its state into unless asked. Click a record to open it there. Key items count too: the scripts, containers, fought monster parties and shops that give one set its held and region flags, a script that takes one clears its held flag, and the item itself is listed with its flags. So do members: a script's AddMember sets the member's joined flag and clears their left flag, RemoveMember the other way, and the member's record is listed with their joined, left and died flags. The index matches the ROM's research atlas use for use on the map objects, on the scripts' and shops' key items, and on the scripts' members. Boss flags, which winning a battle sets, come with combat (2.5).
- **Searching script text:** the list's search also finds scripts by what they say, from three letters, and shows the first line that matches in place of the summary.
- **Many objects at once.** Every mesh the N64 material draws has instance uniforms, so the project raises Godot's global shader variable buffer (`rendering/limits/global_shader_variables/buffer_size`) for a whole map set's worth.
- **Freeing what's out of the tree.** Godot frees only what's in the tree when it quits, and reports everything else leaked, one by one, which after a map set took long enough to look like a hang. The browser swaps the model view and the map view in and out of the preview rather than rebuilding them, and `Models` keeps each scene's parsed template out of the tree, so `RecordBrowser` frees the view not showing and disposes the models when it's deleted, as `Game` disposes its models. Anything else kept out of the tree needs the same.
- **For scripts and screenshots:** `tools/godot.ps1 --path src/Aidyn.Inspector -- --record aidyn:mapset/0 --tab preview --screenshot out/shot.png` opens a record, saves the window and quits. `--tab` takes `preview`, `fields` or `used-by`, and `--data` a plugins folder. `--checkpoint <state>` and `--save <save>` load a checkpoint's or a save's game, `--play <moves>` plays a script that many moves (taking first choices), with its conversation box, or the Party tab, at `--zoom <1-3>`, `--ui-filter pixels|videoout|smooth`, `--aspect 4:3|16:9` and `--ui-lines <n>`, `--drive <request>` drives an actor, `--wireframe 1` and `--scene-camera 1` set those switches, `--collision surface|role` colours a map's collision, `--member <slot>`, `--list inventory|spells|skills|stats`, `--row <n>` and `--details 1` set the Party tab, `--press a,b,up,down` presses its buttons in turn, `--roll 1` rolls a loot table's page or opens a container's in the loot window, whose buttons `--press` also takes with `left` and `right`, `--look 1` looks through a camera object's camera after the wait, and `--wait <seconds>` waits before the screenshot. `--ui-screenshot <png>` saves the UI screen too, in its own pixels. It gives up after a minute, so a hang can't block a script.
