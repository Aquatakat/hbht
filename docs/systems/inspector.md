# The editor (roadmap 0.6)

Per [ADR 0009](../adr/0009-code-organisation.md), the Inspector is the one tool app, and the HTML viewers in `tools/` get no new features. Per [ADR 0010](../adr/0010-editor-reads-plugins.md), it becomes the editor, which reads only the imported plugins and draws them with the runtime's code. The CLAUDE.md status lists the steps to parity with the viewers.

`src/Aidyn.Inspector` is a Godot app. Run it with `tools/godot.ps1 --path src/Aidyn.Inspector` (build it first with `dotnet build`, or open it in the editor). It has two tabs: **Plugins**, the editor, and **ROM Borgs (frozen)**, the raw Borg browser.

## Plugins

It loads the plugins folder as the runtime does (`PluginSet.LoadInstalled`: `aidyn.base`, then the rest by ID), from the data folder (`AIDYN_DATA`, else `%LOCALAPPDATA%\Aidyn`) or wherever **Plugins folder…** points. **Import ROM…** runs the importer into that folder's `aidyn.base`, as the game's first-run screen will, and reloads.

- **The list** is every record and every asset, by type: `PluginCatalog` in `Aidyn.Plugins`, which the tests check against a fresh import. Scenes, textures and UI images are assets with no record, so they're listed by their asset's ID. The Borg column is the archive index a base-game ID's hex key stands for. The summary names what the ID alone doesn't: where a map set places a map (`Overworld I08`) and what objects it holds, an actor's states and scene, a terrain's sky gradient, an image's size, and for a bare asset how many records use it. The search filters by ID, Borg index or summary, so `I08` finds the chunk's map. Enter opens a record ID typed in full, or the only match.
- **Links.** Any field whose value parses as a record ID is a link, so new record types need no editor code. Double-click one in the fields or in Used by to open it on its preview; picking from the list keeps the tab you're on. Back and forward are the ◀ ▶ buttons, Alt+Left and Alt+Right, or the mouse's side buttons. A link to a record no plugin has yet, such as a flag, is dimmer, and opening it shows what names it.
- **Preview.** A scene in the model view, with the N64 material. Drag to turn, right-drag to pan, scroll to zoom.
  - **Animations** play looped, one at a time. The slider scrubs by the tick; with the view focused, space plays and pauses, and comma and full stop step a tick. A clip's length is one loop, as the runtime counts it.
  - **Wireframe**, and **Scene camera**, which looks through the scene's own camera at 4:3, as the scene viewer's did.
  - **Emitters** marks each particle emitter on the scene's own locators (the importer's `emitter i` nodes), drawn through the model in its particles' brightest colour, and counts the scene's emitters and how many sit on its locators.
  - **An actor** is its scene in its initial state, without Alaron's head for now, with its states below: each state's animation, length and branches, with the interrupting ones in orange. Clicking a state plays its animation. **Root in place** zeroes the root transform's position as the game draws it. **Drive** runs the state machine for a request with the runtime's own `ActorAnimator` and the core's `ActorStateMachine`, so the actor branches, rolls and moves by its root motion as it does in the game, and the camera follows it over a grid a scene unit square. Clicking a state enters it, and ⟲ puts the actor back.
  - **A flag** shows whether it's set, its label, a derived flag's formula with each input's value (the first input is the lowest bit), and the journal entry it adds. A plain flag has a check box to set or clear it and see what follows. A journal entry shows its text, the flag the journal lists it by, and the flag that adds it. The values are a new game's until **Load checkpoint…** reads an ares state's flags (see the [reference rig](../reference-rig.md)): it restores the plain flags, evaluates the rest with the core's network, and says whether they match the console's. Any flag the console has otherwise is marked. **New game** goes back.
  - **A script** is its nodes as a graph of cards. A run of lines, each the only way into the next, is one card, read down; a card ends where the script branches, and a new one starts where branches join. Cards read across: a card's first link goes to its right, level with where it leaves, and each other branch goes below it, as high as it fits without meeting the cards above. Double-clicking a link scrolls to the card at its far end. Ifs are gold, cases orange and menus blue. Each node shows its text, its ops with the records they name as links (speakers, flags, items, the script a random line comes from), and, at the end of its card, where it goes. The graph opens centred on the first node, with the zoom controls at the bottom right beside the minimap, as in the Atlas. **Play** runs it with the core's `ScriptRunner` against the flags the editor shows, so load a checkpoint on a flag page first to play a scene as it stands there. The page shows the line and its speaker, and the choices; the graph centres on the node on screen and lights it up in its card. Beside it, a control answers each thing the script checks other than flags: whether each member it asks about is in the party, each item held, the best level in each skill it checks, the party size and gold. Below, it logs the cameras, actors and sounds it cues, what it gives and takes, and each flag it sets or clears. Playing changes the editor's flags, as a flag's check box does.
  - **A map set** is drawn whole with the runtime's code (ADR 0010): each chunk's scenes and scene objects as `ChunkScenery` builds them for the runtime's chunk streamer, each object at its nearest level of detail, with billboards turned to the camera and textures scrolling. A **map** is the 3×3 chunks around it, as the game loads them, framed on its own; **Whole map set** loads the rest. Chunks load nearest first, a few a frame; the overworld takes about 9 seconds and draws at about 30 fps whole. Drag to turn and right-drag to pan. Scrolling moves the camera toward whatever collision is under the cursor, a fifth of the way a notch, and makes that the point it turns about, so it can close in on the ground from any height; over nothing, it flies along the cursor's line. W, A, S and D fly forward, left, back and right, E and Q up and down, Shift faster, at a pace that suits how far away what's in view is. Double-click the ground to turn about that point. The clip planes are fixed, so nothing near the camera is cut away however far out it started.
    - **Terrain** and **Scenery** switch the chunks' scenes and the scene objects' models. **Collision** colours each triangle by surface or by role, see-through over the scenery. **Chunk grid** outlines and names each chunk.
    - **Objects** puts a dot on every map object, coloured by type as the map viewer did; the legend below counts each type and switches it, with scenes and reference points off to start with. Hovering names the object under the cursor, or else the chunk, surface, role and whether the triangle is passable or see-through, with its position in the map set and in the chunk. Clicking a dot opens the object.
    - **Expansion Pak** shows the objects and scenery for playing with it, as the runtime does, or without, and dims the triangles that are passable without it. **Flags** leaves out what isn't there with the editor's flags as a chunk loads (the core's `MapObjectPresence`): a new game's, or a checkpoint's loaded on a flag page.
  - **A map object** (`aidyn:voxel/<map>/<index>`) has a page of its own: its map's chunks with it picked, its radius drawn and a line to each object it names, and its fields beside them, from its map record. Its header says what it is and where, Used by lists what names it (a teleporter arriving at a reference point, a party's home node), and the Atlas its flags. Links between objects open the other object, in another map set if need be.
  - **Other kinds.** A texture or UI image at its size, blown up. Other records show the images they name, such as a terrain's sky gradient or the sky's sun, moon, stars, clouds and flare; click one to open it.
- **Fields:** the merged record as its JSON, with the plugins that set each top-level field, in load order (`PluginSet.Setters`). Lists come in pages of 256. The header says which plugin defines the record, which patch it, and which plugin each asset file comes from.
- **Used by:** every record that names this one, with the fields that do, which is Bethesda's "use info". It's how to find what places a scene, or which maps' objects a flag gates. Terrains show nothing here, since chunks name them by number rather than record ID.
- **Atlas:** the quest atlas, over the plugins' records (`QuestIndex` in `Aidyn.Plugins`). For a flag, what sets, clears and reads it: script ops by node, scripts' done and battle flags, derived flags' formulas, journal entries, the engine, and map objects: their gates, what using them writes (containers opened or destroyed, parties talked to or beaten, locks picked, traps disarmed, secret doors found, triggers). For a script, journal entry or derived flag, the flags it reads and sets, and for a map, its objects'. A script also lists what starts it: the dialogue objects and monster parties that start it, and the scripts whose RandomLine ops take lines from it. A map object is named by what it is and the chunk it's in, such as "Monster party: Male Commoner, in Overworld E15". Below, the graph around it, with edges the way things happen: from what sets a flag, to the flag, to what reads it, and from what starts a script to the script. It follows upstream (what leads to it), downstream (what it leads to) or both, for a number of steps, up to 160 records, and hides the flags the engine writes its state into unless asked. Click a record to open it there. The index matches the ROM's research atlas use for use on the map objects, but for the key items and bosses it gives, which come with 2.3.
- **Searching script text:** the list's search also finds scripts by what they say, from three letters, and shows the first line that matches in place of the summary.
- **Many objects at once.** Every mesh the N64 material draws has instance uniforms, so the project raises Godot's global shader variable buffer (`rendering/limits/global_shader_variables/buffer_size`) for a whole map set's worth.
- **For scripts and screenshots:** `tools/godot.ps1 --path src/Aidyn.Inspector -- --record aidyn:mapset/0 --tab preview --screenshot out/shot.png` opens a record, saves the window and quits. `--tab` takes `preview`, `fields` or `used-by`, and `--data` a plugins folder. `--checkpoint <state>` loads a checkpoint's flags, `--play <moves>` plays a script that many moves (taking first choices), `--drive <request>` drives an actor, `--wireframe 1` and `--scene-camera 1` set those switches, `--collision surface|role` colours a map's collision, and `--wait <seconds>` waits before the screenshot. It gives up after a minute, so a hang can't block a script.

## ROM Borgs (frozen)

The raw Borg browser gets fixes only (ADR 0010), and is deleted with the HTML viewers. It reads the ROM only once its tab is opened. It finds the ROMs in `roms/` (or `AIDYN_ROMS`) by hash and opens 1.0 first, or use **Open ROM…**.

- **The list** filters by type, and by index or summary text. Summaries fill in as it decodes the archive in the background, which takes a few seconds.
- **Preview:** textures with every mip level, and UI images. Models are shown alone and untextured, since scenes bind the textures. Scenes play all their animations. An animation plays in its scene, an actor plays its initial state, and a map chunk's collision shows where its first map set places it. Dialogue shows as text. Drag to turn, right-drag to pan, scroll to zoom. The 3D views are the CLI's glTF, loaded at run time with Godot's `GltfDocument`, so they match the scene viewer.
- **Godot loses texture wrap modes on import.** A `BaseMaterial3D` has one repeat switch for both axes and can't mirror, so glTF's mirrored repeat and one-axis clamp come out wrong. Faces are often half a texture mirrored across the middle (Donovan, scene 10363, lost half his face), and the knight's pauldrons (scene 9765) and the Gwernia house's door clamp or mirror too. `WrapMaterials` swaps those materials for a shader that wraps each axis itself. The runtime's N64 material will need the same.
- **Fields:** the decoded record, read by reflection, so a new decoder's fields show up with no inspector code. Lists expand in pages of 256. The Borg's `Borg_List` entry is below it.
- **Hex:** the decompressed bytes. Samples and sequences (1D) have only this so far.
- **For scripts and screenshots:** `--borg 10723` (and `--rom <path>`) opens this tab at a Borg, with `--tab preview|fields|hex` and `--screenshot` as above.

The decoding lives in `Aidyn.Rom.Inspection` (`BorgInspector`, `FieldTree`), which the tests check against every Borg; the Godot project is only UI. Like the CLI, it reads the ROM through `Aidyn.Rom` as a research tool. The editor won't: ADR 0010 keeps it on plugins, like the runtime.
