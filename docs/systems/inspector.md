# The editor (roadmap 0.6)

Per [ADR 0009](../adr/0009-code-organisation.md), the Inspector is the one tool app. Per [ADR 0010](../adr/0010-editor-reads-plugins.md), it's the editor, which reads only the imported plugins and draws them with the runtime's code. New research into formats uses the CLI's dumps and exports.

`src/Aidyn.Inspector` is a Godot app. Run it with `tools/godot.ps1 --path src/Aidyn.Inspector` (build it first with `dotnet build`, or open it in the editor). It draws with the views it shares with the runtime in `Aidyn.Views` (ADR 0022), and the runtime uses nothing of the editor's.

## The editor's game

The editor holds one game, the core's `GameState` ([saves](saves.md)), which flag pages show and set, scripts play against and change, and the party's pages show or try things on. Its sky, over the chunk it stands in at its time of day (`EditorGame.Sky`), lights the previews' lit meshes as trek's sky lights the runtime's ([rendering](rendering.md#the-n64-material)). A flag page's buttons change it:

- **Load checkpoint…** reads an ares state (see the [reference rig](../reference-rig.md)) as a save made from it loads (`CheckpointSave`), and says whether the core's network reproduces the console's derived flags, marking any the console has otherwise (such as the new journal entry flag, which loading clears). A state without a party gives a new game's party with the checkpoint's flags.
- **Load save…** loads a save from the data folder's `saves` and lists anything it couldn't use.
- **Save game…** saves the game as the editor has it, where the save or checkpoint it came from stood, so the runtime can start from it (`--save`).
- **New game** goes back to a new game's.

## Plugins

It loads the plugins folder as the runtime does (`PluginSet.LoadInstalled`: `aidyn.base`, then the rest ordered by their dependencies and load-after hints, by ID where those leave it open), and shows `BasePlugin.Diagnose`'s words instead of loading when the import is missing or by another importer, from the data folder (`AIDYN_DATA`, else `%LOCALAPPDATA%\Aidyn`) or wherever **Plugins folder…** points. **Import ROM…** runs the importer into that folder's `aidyn.base` and reloads.

- **The list** is every record and every asset, by type (`PluginCatalog` in `Aidyn.Plugins`). Scenes, textures and UI images are assets with no record, so they're listed by their asset's ID. The Borg column is the archive index a base-game ID's hex key stands for. The search filters by ID, Borg index or summary (`I08` finds the chunk's map), and from three letters finds scripts by what they say, showing the first line that matches.
- **Links.** Any field whose value parses as a record ID is a link, so new record types need no editor code. A link to a record no plugin has, such as a flag, opens a page showing what names it.
- **Preview** (`RecordBrowser` picks the panel). Each kind of record previews with the runtime's or the core's own code, against the editor's game where rules come in:
  - **A scene** in the model view (`ModelView`) with the N64 material: its animations, looped and scrubbed by the tick, with **Wireframe**, **Scene camera** (the scene's own camera at 4:3) and **Emitters** (each particle emitter marked on its locator). A clip's length is one loop, as the runtime counts it.
  - **An actor** (`ActorPanel`): its scene in its initial state, without Alaron's head, and its states and branches. **Root in place** zeroes the root's position as the game draws it, and **Drive** runs the state machine for a request with `ActorAnimator` and `ActorMotion`, moving it by its root motion and starting its emitters as it enters states ([particles](../formats/particles.md)): `--record aidyn:actor/0x2BD7 --drive 5` shows Oriana's orb.
  - **A flag** or **journal entry** (`FlagPanel`): its value in the editor's game, its label, a derived flag's formula with each input's value (the first input is the lowest bit), and a check box to set a plain flag.
  - **A script** (`ScriptPanel`): its nodes as a graph of cards, a card being a run of lines that each lead only to the next. **Play** runs it with the core's `ScriptRunner` against the editor's game (`GameState.RunScript`, so it draws from the game's random streams as the runtime's do), drawing the conversation box ([ui](ui.md)). What the script asks about (members, items, gold, any skill check fixed at a step) can be changed in place; what it does changes the editor's game, and its cues and transitions are logged.
  - **An entity** (`CharacterPanel`): its character sheet from the core's `Character`, with training quoted by the core's `Training`, experience to award, and equipment taken off or put on by the core's rules. A member of a loaded game's party can show that game's sheet. A trainer's page ends with the training window ([ui](ui.md#training)).
  - **A weapon, armor or item, a shop, a loot table or a recipe** (`ItemPanels`): tried on a copy of the editor's party (`GameState.CopyParty`), so trying things leaves the game alone. A shop opens its window on the editor's game ([ui](ui.md#the-shop)), so the barterer pays its Stamina; a loot table rolls once into the loot window ([ui](ui.md#the-loot-window)), or 10,000 times for its averages.
  - **The inventory record** (`aidyn:inventory/0`, `PartyTabPanel`): the editor's game's party in the Party tab, drawn by `PartyTabView` ([ui](ui.md#the-pause-menu)), with buttons for the controller's. It, `BarterWindowPanel` and `TrainingWindowPanel` are `MenuWindowPanel`s, which hold the UI screen and its options, the button bar, the Details checkbox and `--press`'s names for the window they preview (an `IPartyWindow`).
  - **A map set or a map** (`MapSetView`): drawn whole with the runtime's `ChunkScenery` (ADR 0010), each object at its nearest level of detail; a map is its 3×3 framed on its own, and **Whole map set** loads the rest. Switches for terrain, scenery, collision coloured by surface or role (`CollisionLayer`), the chunk grid, the map objects by type (`MapObjects`; their names are Plugins' `MapObjectKinds`), the Expansion Pak, and **Flags**, which leaves out what isn't there by the editor's game's flags (the core's `MapObjectPresence`). The camera is `Orbit`.
  - **A map object** (`aidyn:voxel/<map>/<index>`): its map's chunks with it picked, its radius and a line to each object it names. A container can be opened in the loot window, rolling what it holds without setting its flags, and a camera object looked through, from where the player triggers it.
  - **Textures, UI images** and the images other records name (`ImageGallery`), blown up; click one to open it.
- **Fields:** the merged record as its JSON, with the plugins that set each top-level field, in load order (`PluginSet.Setters`); a map object's fields are its map's `objects[<index>].<field>`, so a mod that patched one object shows on that object alone. Lists come in pages of 256. The header says which plugin defines the record, which patch it (`PluginSet.Patchers`), and which plugin each asset file comes from. The status line after loading counts the fields more than one plugin patched ([importer](importer.md), the conflict report).
- **Used by:** every record that names this one, with the fields that do. Terrains show nothing here, since chunks name them by number rather than record ID.
- **Atlas** (`AtlasView`, over `QuestIndex` in `Aidyn.Plugins`): for a flag, what sets, clears and reads it, from scripts, derived flags, journal entries, the engine, map objects and chunks' world map regions; for a script, what it reads and sets and what starts it. Below, the graph around it, upstream, downstream or both, up to 160 records (`AtlasView.NodeLimit`), hiding the flags the engine writes its state into unless asked. Key items and members count as their flags: giving a key item sets its held and region flags, and AddMember sets a member's joined flag. The CLI's `aidyn flag` reads the same index. Boss flags, which winning a battle sets (`CombatRecord.Bosses`), and trigger records aren't in the index yet.

## Traps

- **Many objects at once.** Every mesh the N64 material draws has instance uniforms, so the project raises Godot's global shader variable buffer (`rendering/limits/global_shader_variables/buffer_size`) for a whole map set's worth.
- **Freeing what's out of the tree.** Godot frees only what's in the tree when it quits, and reports everything else leaked, one by one, slow enough after a map set to look like a hang. The browser swaps the model view and the map view in and out of the preview rather than rebuilding them, and `Models` keeps each scene's parsed template out of the tree, so `RecordBrowser` frees the view not showing and disposes the models when it's deleted, as `Game` disposes its models. Anything else kept out of the tree needs the same.

## The command line

`tools/godot.ps1 --path src/Aidyn.Inspector -- --record aidyn:mapset/0 --tab preview --screenshot out/shot.png` opens a record, saves the window and quits. It gives up after a minute, so a hang can't block a script. `Editor` parses the options and takes the screenshot with the views' `CommandLine`, as the runtime does.

- **The page:** `--record <id>`, `--tab preview|fields|used-by|atlas`, `--data <plugins folder>`.
- **The game:** `--checkpoint <state>` or `--save <save>` loads that game; `--play <moves>` plays a script that many moves, taking first choices, with its conversation box.
- **The UI screen** (the conversation box and the windows): `--zoom <1-3>`, `--ui-filter pixels|videoout|smooth`, `--aspect 4:3|16:9`, `--ui-lines <n>`.
- **Scenes and maps:** `--drive <request>` drives an actor; `--wireframe 1` and `--scene-camera 1` set those switches; `--collision surface|role` colours a map's collision; `--look 1` looks through a camera object's camera.
- **The Party tab and windows:** `--member <slot>`, `--list inventory|spells|skills|stats`, `--row <n>`, `--details 1`; `--roll 1` rolls a loot table or opens a container's loot window; `--press a,b,up,down` presses a window's buttons in turn, with `left` and `right` in the loot window, `cup` in a shop's and `cleft` and `cright` in a training window.
- **Screenshots:** `--wait <seconds>` waits first; `--ui-screenshot <png>` saves the UI screen too, in its own pixels.
