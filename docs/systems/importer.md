# The importer and the base plugin (M1)

`aidyn import <rom>` turns a ROM into `aidyn.base`, the plugin the runtime loads (ADR 0001). It goes to `plugins/aidyn.base` in the data folder: `AIDYN_DATA` if set, else `%LOCALAPPDATA%\Aidyn`. `--out` puts it elsewhere. It refuses the debug ROM (ADR 0007).

- **Layout.** `plugin.json` records the importer version (`BasePlugin.ImporterVersion`) and the ROM's SHA-1, so the runtime can tell when to re-import. `records/` holds the record files below; the loader reads every JSON file under `records/`, whatever the layout (ADR 0005), so the split is only for reading and diffing. Maps are a file per map set (`maps/Overworld.json` and so on), since each map is in one set; the runtime still loads every map record at start. `assets/aidyn/<type>/<key>.glb` holds every scene (`aidyn:scene/0xHHHH`, the same glTF as `aidyn scenes`) and every chunk's collision (`aidyn:map/0xHHHH`, in the chunk's own coordinates); every texture is a PNG (`aidyn:texture/0xHHHH`, full size only) and every UI image one too (`aidyn:image/0xHHHH`, which includes the sky gradients). Scenes carry their own textures; the texture records are for what the engine draws with a texture alone, such as bodies' shadows and particles. A mod replaces an asset by putting a file at the same path in its own `assets/`. The core reads some assets itself, headlessly: chunks' collision (`CollisionMesh`), scenes' triangles (`SceneMesh`), actors' timing and root motion from their scenes' animations (`ActorClips`), and images' sizes from their PNGs' headers (`PluginSet.ImageSize`), which the sky's sprites and the minimap are placed by.
- **Scenes have locator nodes** (`locator <i>`, under their transform), for what the game attaches at run time. Alaron's actor record names his head scene and its locator.
- **Records.**
  - Map sets are `aidyn:mapset/<n>`, numbered as the original's `EnumMapDatA`, with the cell size and chunk list. A map (`aidyn:map/0xHHHH`, a Borg9) holds its map objects of every type but the code objects, keyed by index (see [maps](../formats/maps.md#map-objects-in-the-base-plugin-06)). Scene objects' models name a scene or an actor, and they keep the original's rotation angles.
  - Actors (`aidyn:actor/0xHHHH`) hold their scene and state machine. Terrains (`aidyn:terrain/<n>`, 0–27) name their sky gradient and whether it's drawn (see [rendering](rendering.md)), and the Battle arenas their battles take (see [combat](combat.md)). The combat record (`aidyn:combat/0`, `combat.json`, `CombatImporter`) holds who fights with the party, who never fights, the Skeleton and the flee rules. Spells and potions carry their effects (importer 40, `MagicImporter`, ADR 0020): the ROM keeps none of it as data, since the original's code switches on a spell's kind, so each spell's effects, duration, resist rule, target filter and AI value are facts checked against 1.0's machine code, and the importer fails on a spell without one, a fact without a spell, or a name or entity place that differs. The magic record (`aidyn:magic/0`, `magic.json`) holds casting's numbers, with its float tables read from the code segment (`CodeTable.CastingFactors`, `CastingFactors`).
  - `sky.json` is the one sky record (`aidyn:sky/0`): the sun, moon and stars, the clouds and the lens flare's pieces, read from the code segment, with the UI images they are drawn with. The images are literals in engine code, so the importer carries them as facts (`Skies`) and refuses a ROM where one isn't a UI image.
  - `sequences.json` holds every Borg12 as `aidyn:sequence/0xHHHH`, whose events are the asset `sequence/0xHHHH.dcm`, and every Borg11 is `sample/0xHHHH.wav` ([audio](../formats/audio.md#in-the-base-plugin)). `sounds.json` is the one sounds record (`aidyn:sounds/0`): what the menus, scripts, containers and weather play, and the bodies' footsteps by kind; the map sets' music is on their records, and bodies' audio keys on the entities' ([audio](audio.md#whats-ported)).
  - `emitters.json` holds each scene's particle emitters as `aidyn:emitters/0xHHHH`, keyed by the scene, with each emitter's texture slot looked up in the engine's particle list (`partTextInds`) to a texture record ([particles](../formats/particles.md)). `cinematics.json` holds the four cinematics (`aidyn:cinematic/0`–`3`): each shot's animation, music and near and far planes, and the flag set at the end. `credits.json` holds the credits (`aidyn:credits/0`).
  - The fonts (`aidyn:font/<n>`) and the string tables (`aidyn:strings/<n>`) are in `fonts.json` and `strings.json`, and entities and dialogue entities carry their portraits (see [text](../formats/text.md)). The flags, journal and state flags, the scripts (`dialogue.json`) and the DB tables' records (`entities.json`, `items.json`, `weapons.json`, `armor.json`, `spells.json`, `skills.json`, `shops.json`, `loot.json`, `recipes.json`, `inventory.json`, `minimaps.json`, `worldmap.json`, `weather.json`, `camping.json`, `newgame.json` (`aidyn:newgame/0`, where a new game starts and who leads, [runtime](runtime.md)) and the rest of `records/`) are there too; each is described with its system.
- **Code.** `BaseImporter.Import` stages the plugin in a sibling folder and moves it into place when it's done. An `ImportContext` holds what the families share: the ROM, its Borg archive and DB, each code-segment table read once on first use (`EngineTables`, `BodySoundTables`, `AudioTables` and the rest), and the writers for records and assets. An importer per family builds its records from it: `WorldImporter` (map sets, terrains, weather, the World tab's map, camping, the sky), `FlagImporter` (flags, journal, state flags), `CharacterImporter` (dialogue entities' names, entities, spells, stats, skills, progression), `ItemImporter` (weapons, armor, items, loot, shops, recipes, inventory), `TextImporter` (strings, fonts), `DialogueImporter` (Borg13 scripts), `CinematicImporter` (the four cinematics, the credits), `MapImporter` (minimaps, maps and their collision), `GraphicsImporter` (actors, scenes and their emitters, textures, UI images) and `AudioImporter` (the sounds record, sequences, samples). `BodySoundImporter` and `MinimapImporter` build the sounds and minimap records the others write. A reader of the ROM's bytes uses `Be` (big-endian fields, tables as arrays, lists up to a terminator, a Borg's bounds-checked slice) and `RomImage.Table` for a table's range in the version's layout.
- **Deterministic.** Two imports are byte-identical, which a test checks. JSON is indented, with vectors and colours on one line, so two imports diff cleanly.
- **Merging** follows ADR 0005: patches merge field by field (RFC 7386), and `PluginSet.Conflicts` lists the top-level fields more than one plugin set. Lists are still replaced whole. Keyed lists need the record schema, which is Phase 5 work.
- **Reading records.** `PluginSet.Get`, `TryGet` and `All` read the merged JSON as a record type once and keep it: every later call for that record and type returns the same object, and `All` holds those same objects, in the order of their IDs' spelling. The records are immutable, and nothing changes the merged JSON once the set has loaded (`GetJson` hands out the set's own, to read), so the cache never goes stale; it's safe from the audio thread. A record read as two types, as `DbRecord` reads part of an entity's, is one object per type. A type there's only one of (`aidyn:camping/0`, the sky, the sounds, the credits and the like) is read with `Singleton` or `TrySingleton`, which take its `aidyn:<type>/0`; a mod patches it rather than adding another.
