# The importer and the base plugin (M1)

`aidyn import <rom>` turns a ROM into `aidyn.base`, the plugin the runtime loads (ADR 0001). It goes to `plugins/aidyn.base` in the data folder: `AIDYN_DATA` if set, else `%LOCALAPPDATA%\Aidyn`. `--out` puts it elsewhere. It takes about 8 seconds and writes about 270 MB. It refuses the debug ROM (ADR 0007).

- **Layout.** `plugin.json` records the importer version (`BasePlugin.ImporterVersion`) and the ROM's SHA-1, so the runtime can tell when to re-import. `records/` holds `mapsets.json`, `terrains.json`, `sky.json`, `actors.json`, the flags, journal and state flags, the scripts (`dialogue.json`), the DB records' names, and the maps a file per map set (`maps/Overworld.json` and so on), since each map is in one set. The loader reads every JSON file under `records/`, whatever the layout (ADR 0005), so the split is only for reading and diffing: the runtime still loads every map record at start. `sky.json` is the one sky record (`aidyn:sky/0`): the sun, moon and stars, the clouds and the lens flare's pieces, read from the code segment, with the UI images they are drawn with. The images are literals in engine code, so the importer carries them as facts (`Skies`) and refuses a ROM where one isn't a UI image. `assets/aidyn/<type>/<key>.glb` holds every scene (`aidyn:scene/0xHHHH`, the same glTF as `aidyn scenes`) every chunk's collision (`aidyn:map/0xHHHH`, as `aidyn maps` writes it but in the chunk's own coordinates), every texture as PNG (`aidyn:texture/0xHHHH`, full size only), and every UI image as PNG (`aidyn:image/0xHHHH`), which includes the sky gradients. Scenes carry their own textures; these are for what the engine draws with a texture alone, such as bodies' shadows and particles. A mod replaces an asset by putting a file at the same path in its own `assets/`.
- **Scenes have locator nodes** (`locator <i>`, under their transform), for what the game attaches at run time. Alaron's actor record names his head scene and its locator.
- **Records so far.** Map sets are `aidyn:mapset/<n>`, numbered as the original's `EnumMapDatA`, with the cell size and chunk list. A map (`aidyn:map/0xHHHH`, a Borg9) holds its map objects of every type but the code objects, keyed by index (see [maps](../formats/maps.md#map-objects-in-the-base-plugin-06)). Scene objects' models name a scene or an actor, and they keep the original's rotation angles. Actors (`aidyn:actor/0xHHHH`) hold their scene and state machine. Terrains (`aidyn:terrain/<n>`, 0–27) name their sky gradient and whether it's drawn (see [rendering](rendering.md)). The rest of the DB tables come with the tracks that use them.
- **Deterministic.** Two imports are byte-identical, which a test checks. JSON is indented, with vectors and colours on one line, so two imports diff cleanly.
- **Merging** follows ADR 0005: patches merge field by field (RFC 7386), and `PluginSet.Conflicts` lists the top-level fields more than one plugin set. Lists are still replaced whole. Keyed lists need the record schema, which is Phase 5 work.
