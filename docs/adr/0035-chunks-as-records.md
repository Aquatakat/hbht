# 0035. Chunks as records: one record per cell, keyed by its map set and name

Status: Accepted · Nov 3, 2026

## Context

Four records described one cell of the world: the map set's `chunks[]` entry (its scenes, terrain, music and so on), the `map` record its entry named (`aidyn:map/0xBORG`: the map objects, the grid and the neighbours drawn), the map's collision asset, and a `minimap` record per map set. The map was keyed by its Borg9, which the original reuses to save ROM: 9 Borg9s are shared, the 141 sea cells of the Overworld on `0x3559` and 21 of the 28 Battle arenas on 8 others. So a map object's ID, `aidyn:voxel/0x0E88/3`, named an object in up to five cells, which a save's memory of it or a mod's patch couldn't tell apart. Other records named a cell four ways: a `ChunkRef` of map set, row and column (teleporters, script objects' stages, the new game, a battle's end), a bare Overworld row and column (the title's fly-throughs), a range of arena numbers (terrains), and an int for a terrain. A monster party meant two things, an NPC to talk to or a fight, and its flag slots meant different things in each; the battles with rules of their own were found by their encounter flag in two lists on the combat record.

## Decision

- **A chunk is a record**, one per cell: `aidyn:chunk/<map set>/<name>`, such as `aidyn:chunk/8/C05`. The map set is the original's number (`Zones.SetMapSet`, `0x80026264`) and the name the original's own, `"New Grid: %d-%c%02d"` in the debug build: the row's letter (`row − 1 + 'A'`) and the column in two digits. A cell the original can't name that way, a row outside A–Z, is named `<row>_<column>`, such as `0_13` and `-1_13`: the 24 sea cells the importer makes north of the Overworld's row A (0030's fills). A mod's chunk is keyed by a name of its own (`mymod:chunk/hermit_isle`).
- **The chunk holds everything about its cell**: `mapSet`, `row`, `column` (its place), `borg` (the Borg9 it came from, for the emulator and AidynEditor; nothing reads it), `collision` (its collision asset, `aidyn:collision/0xBORG`), `scene`, `altScene`, `terrain` (a terrain's ID), `music`, `region`, `swap`, `fill`, `extended`, `shows` (chunk IDs), `drawnNeighbours`, `grid` and `objects`. The 9 shared Borg9s are copied into each cell's chunk, so every object has one ID; their collision stays one asset, which each of those chunks names.
- **A map set doesn't list its chunks.** The plugin set indexes chunks by their cell, and a mod adds a cell by adding a chunk. Two chunks claiming one cell is a validation problem, blamed on the later plugin. `mapset` keeps `label`, `cellSize`, `music` and `spawns`, and the minimap folds into it as `minimap`, whose sections and rules keep their rows and columns within the set. The `map` and `minimap` types go.
- **A map object is `aidyn:mapobject/<map set>/<name>/<index>`** (a mod's chunk's, `mymod:mapobject/hermit_isle/3`), its chunk's key and its index, which stays the ROM's. The `voxel` ID goes; "voxel" is the original's word, used only to cite it. Every reference moves: links, homes, wander nodes' `next`, cameras' reference points, teleporters' arrivals and cameras, the camping record's campsite, the game over's script object, triggers' `script.start`, and saves' memories.
- **A reference to a cell is a chunk ID**: a teleporter's `destination` (written only without an `arrival`, whose chunk it is), a script object's `stage`, a non-lethal battle's `end.place`, the new game's `chunk`, the title's fly-throughs' `chunk` and `origin`, and a terrain's `arenas`, which are groups of arena chunks (a battle rolls one of a group; with two groups, a d2 picks the group first). A script's `battle.arena` names its arena's chunk, and the combat record's `defaultArena` is the one a script's battle takes when it names none. The world map's ring and the spawns keep their rows and columns, as geometry within their set.
- **A monster party is an `encounter` or an `npc`**, by whether it has a script. An encounter fights: winning sets `used`, and it's gone while that's set. An npc talks: talking sets `used`; its `enemies`, `loot` and size bounds are optional, for the talkers whose script starts a battle (the original fights the party, not the script's list), and `battleFlag` is what winning that battle sets. The importer leaves out the talkers' stand-in enemy lists, which name only the talker, where their script starts no battle. An npc whose cut-scene needs a script object's marks names it in `stage`, and starting its script uses that object's marks and stage (the port's fix, below).
- **A battle's own rules are on what starts it**, as `battleRules`: `{ flee?, nonLethal?, quietVictory?, speaker?, end?, healsLeader?, keelOver? }`, on a script record beside its `battleFlag`, on an npc beside its, and on an encounter. They replace the combat record's `fleeByEncounter` and `encounters`, which keyed them by the encounter flag: the original's flag is the one the battle's source gives (a script's `battleFlag`, a talker's, an encounter's `used`), so the rules sit on that source. The Goblin Ambush's are on script `0x0365` and its three talkers, Lugash's flee on script `0x04D1`, the Marquis's on his npc.

## Consequences

- Every record ID that names a map, an object or a cell changes. The base plugin is re-imported; saves name map objects in their memories, which save format 2's upconverter maps: an old `aidyn:voxel/<borg>/<n>` names one chunk's object unless its Borg9 is shared, when the save's place decides, and otherwise the memory is dropped.
- A chunk is self-contained, so a mod can patch "the chest in Terminor C05" and nothing else, and the editor and the quest atlas find a map object's place from its ID alone.
- The arenas have no numbers of their own: the original's arena numbers (`Zones.ArenaChunks`, `0x800DCA74`, the order of map set 16's chunks) are resolved by the importer into chunk IDs.
- **The npc's `stage` is a fix of the port's, chosen by the user** (0018): 1.0 starts a talker's script from marks 0 in the player's chunk, so a cut-scene that names a point only its script object's marks find reads another scene's points and crashes (Keelin's in Terminor after "Kisses."). The importer sets `stage` where a talker that isn't silent has a cut-scene naming a mark marks 0 doesn't find, and a script object in its chunk playing the same script finds them all: 6 npcs, Keelin among them.
- The base plugin writes a chunk a file, `records/chunks/<map set>/<name>.json`, which 0036 loads lazily.
